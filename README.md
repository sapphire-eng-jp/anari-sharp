# ANARISharp

C# bindings for the [Khronos ANARI](https://www.khronos.org/anari/) rendering API.

The bindings come in two layers:

1. **`ANARISharp.Interop`** - a raw P/Invoke layer generated directly from the ANARI SDK
   headers with [ClangSharp](https://github.com/dotnet/ClangSharp).
2. **`ANARISharp`** - a high-level, idiomatic C# class library modeled on the official
   C++ wrapper (`anari_cpp.hpp`).

## Repository layout

```
ANARISharp.slnx              Solution (dotnet 10 slnx format)
src/ANARISharp/              The bindings library (net8.0, AllowUnsafeBlocks)
  Interop/                   Generated P/Invoke layer (do not edit by hand)
  *.cs                       High-level class library
samples/HelloANARI/          "First frame" tutorial port (renders a triangle to PPM)
tests/AotRootTest/           Native AOT compatibility harness (see "Native AOT" below)
tools/generate.ps1           Regenerates src/ANARISharp/Interop from the SDK headers
```

## Architecture

### Interop layer (`src/ANARISharp/Interop/`)

Generated by `tools/generate.ps1`; regenerate whenever the ANARI SDK is updated.

- **`ANARI.cs`** - all 38 C API entry points from `anari.h` as
  `[DllImport("anari")]` methods on the static class `ANARI`. The header is parsed in
  **C++ mode** on purpose: the empty `anari::api` handle structs (`Device`, `Camera`,
  `Array1D`, ...) become distinct C# structs, so every function signature uses typed
  handle pointers (`Device*`, `Camera*`) instead of untyped `void*` - the same type
  safety the C++ API gets from its handle typedefs. Callbacks
  (`ANARIStatusCallback`, `ANARIMemoryDeleter`) are surfaced as
  `delegate* unmanaged[Cdecl]<...>` function pointers.
- **Handle structs** (`Device.cs`, `Camera.cs`, ...) - one empty struct per ANARI
  object type, used only as pointer targets.
- **`ANARIEnums.cs`** - C# enums synthesized from the `#define` blocks in
  `anari_enums.h`: `ANARIDataType` (133 values), `ANARIStatusCode`,
  `ANARIStatusSeverity`, `ANARILogLevel`, and `ANARIWaitMask`. The ANARI headers
  define these as `typedef int` + macros rather than C enums, so ClangSharp cannot
  emit enums for them; the generator script parses the defines and emits real enums
  (matching native names and values) instead.
- **`ANARIConstants.cs`** - the same macros as raw `const int` fields, generated by a
  second ClangSharp pass in **C mode** (where `ANARI_DATA_TYPE_DEFINE(v)` expands to a
  plain integer). Kept as the faithful, unprocessed conversion of the header.
- **`ANARIParameter.cs` / `ANARIParameterValue.cs`** - the two C structs from `anari.h`.
- **`NativeTypeNameAttribute.cs`** - hand-written support attribute referenced by the
  generated code (not overwritten by the generator).

The generator script also patches one piece of invalid C# that ClangSharp emits for
`ANARI_DEFAULT_VAL` default arguments (`sbyte* type = "default"u8`).

### High-level layer (`src/ANARISharp/`)

A class library equivalent to `anari_cpp.hpp`:

- **`ANARILibrary`** - wraps the native library handle (`Load`, `LoadModule`,
  `GetDeviceSubtypes`, `GetDeviceExtensions`, `NewDevice`). `Load` accepts a managed
  `ANARIStatusCallback` delegate, bridged to the native callback through an
  `[UnmanagedCallersOnly]` thunk and a `GCHandle` (freed on dispose).
- **`ANARIObject`** - base class for every handle; implements the parameter/lifetime
  surface of anari_cpp:
  - `SetParameter<T>(name, value)` with the ANARI type inferred by
    **`ANARITypeFor<T>`**, the C# equivalent of the `ANARITypeFor<T>` trait in
    `anari_cpp/Traits.h`. Supported types include all integer/float scalars, `Half`,
    `System.Numerics` `Vector2/3/4`, `Matrix4x4` (`ANARI_FLOAT32_MAT4`),
    `Quaternion` (`ANARI_FLOAT32_QUAT_IJKW`), and the `IVec*`/`UVec*` structs.
  - Overloads matching the C++ specializations: `string` -> `ANARI_STRING`,
    `bool` -> `ANARI_BOOL` transported as `uint32`, `ANARIObject` -> the object's own
    handle type, plus `SetParameterAs<T>` and `SetAndReleaseParameter`.
  - `SetParameterArray1D/2D/3D` - directly mapped parameter arrays
    (`anariMapParameterArray*`), handling both dense and strided destinations, with
    an object-handle overload for parameters like `world.surface`.
  - `GetProperty<T>` (with the `bool`-via-`uint32` special case), `UnsetParameter`,
    `UnsetAllParameters`, `CommitParameters`, `Retain`, and `IDisposable.Dispose`
    calling `anariRelease` (idempotent).
- **`ANARIDevice`** - the object factory: `NewCamera`, `NewGeometry`, `NewLight`, ...,
  `NewFrame`, plus `NewArray1D/2D/3D` in three flavors (device-managed by element
  type, copy-from-`ReadOnlySpan<T>`, and zero-copy over caller-owned memory) and
  `GetObjectSubtypes` introspection.
- **Handle subclasses** (`ANARICamera`, `ANARIGeometry`, `ANARISurface`, `ANARIWorld`,
  ... 17 types total) - each overrides `DataType` with its ANARI object type so
  object-valued parameters are typed correctly.
- **`ANARIArray`/`ANARIArray1D/2D/3D`** - track element type and dimensions; `Map<T>()`
  returns a typed `Span<T>` over the mapped memory.
- **`ANARIFrame`** - `Render`, `IsReady`, `Wait`, `Discard`, and `Map<T>(channel)`
  returning a `MappedFrameData<T>` ref struct (width, height, pixel type, and a
  `ReadOnlySpan<T>` sized via `ANARIDataTypeUtil.SizeOf`).
- **`ANARIDataTypeUtil`** - `IsObject`/`IsArray`/`SizeOf` helpers mirroring
  `Traits.h` / `type_utility.h`.

## Native AOT and trimming

ANARISharp is fully compatible with [Native AOT](https://learn.microsoft.com/en-us/dotnet/core/deploying/native-aot/)
and assembly trimming, and declares it via `<IsAotCompatible>true</IsAotCompatible>`
(which also enables the AOT, trimming, and single-file analyzers on every build).

Compatibility falls out of the interop design: every P/Invoke signature is fully
blittable (typed handle pointers, `delegate* unmanaged[Cdecl]` function pointers),
callbacks cross the boundary through `[UnmanagedCallersOnly]` thunks, and the library
uses no runtime marshalling, reflection emit, or dynamic code generation.

`tests/AotRootTest` verifies this beyond the analyzers: it roots the entire assembly
with `<TrimmerRootAssembly Include="ANARISharp" />` so *all* APIs - used or not - are
compiled by the AOT toolchain, then publishes with `PublishAot`:

```powershell
dotnet publish tests\AotRootTest -c Release -r win-x64
```

The publish must complete without IL2xxx/IL3050 warnings. (Outside a Visual Studio
developer prompt, add the VS Installer directory - the one containing `vswhere.exe` -
to `PATH` so the native link step can locate MSVC.)

Note that `anari.dll` and the device libraries are always loaded dynamically at run
time; AOT-published applications must ship them or have them on `PATH`, exactly as in
a JIT deployment.

## Regenerating the bindings

Requires the ClangSharp global tool. Default SDK path is `D:\anari\next_release`:

```powershell
dotnet tool install -g ClangSharpPInvokeGenerator   # once
powershell -File tools\generate.ps1 [-ANARIRoot <path-to-ANARI-install>]
```

## Running the sample

Add the directory containing `anari.dll` and the device libraries to `PATH`, then:

```powershell
$env:PATH = "D:\anari\next_release\bin;$env:PATH"
dotnet run --project samples\HelloANARI            # defaults to helide
dotnet run --project samples\HelloANARI -- visrtx  # pick a library by argument
```

The sample renders an 800x600 vertex-colored triangle and writes `hello_anari.ppm`.

## Usage example

```csharp
using var library = ANARILibrary.Load("helide");
using var device = library.NewDevice();
device.CommitParameters();

using var geometry = device.NewGeometry("triangle");
geometry.SetParameterArray1D("vertex.position", positions);   // ReadOnlySpan<Vector3>
geometry.CommitParameters();

using var frame = device.NewFrame();
frame.SetParameter("size", new UVec2(800, 600));
frame.SetParameter("channel.color", ANARIDataType.ANARI_UFIXED8_RGBA_SRGB);
frame.CommitParameters();

frame.Render();
frame.Wait();
var mapped = frame.Map<byte>("channel.color");
```
